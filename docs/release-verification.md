# Verify an installation or update

Download from [TouchAI releases](https://github.com/TouchAI-org/TouchAI/releases)
or the official update service. Choose the installer for your OS and architecture.
Windows uses MSI/Velopack; macOS uses DMG; Linux provides AppImage, DEB and RPM.
An unpackaged development build is not an installed Velopack app; use the
platform installer if in-app installation is unavailable.

Stable is the normal channel. Beta and Nightly installations initially follow
their own channels; your saved choice takes precedence. Switching channels never
authorizes an in-app downgrade. If Stable is older than the installed Beta, wait
for Stable to catch up. Do not install an older version over a migrated database.
Back up/export data using the app's existing tools before a manual replacement.

## Verify provenance first

Releases produced by the new workflow include `SHA256SUMS`, a
`TouchAI-<version>.source.spdx.json` dependency inventory and
`provenance.sigstore.json`. Older releases do not acquire these retroactively.

Install a current [GitHub CLI](https://cli.github.com/) and verify the **actual
installer file**. Substitute the filename you downloaded:

```sh
gh attestation verify './TouchAI-<version>-windows.msi' --repo TouchAI-org/TouchAI --signer-workflow TouchAI-org/TouchAI/.github/workflows/velopack-build.yml
```

Inspect the verified source commit/ref and compare it with the intended release
tag. A successful check proves the bytes were attested by that repository's
workflow, not that every change is correct or safe. Do not accept an attestation
for a fork or a different workflow just because its filename matches.

The published bundle can also be used without downloading the attestation again:

```sh
gh attestation verify './TouchAI-<version>-windows.msi' --bundle ./provenance.sigstore.json --repo TouchAI-org/TouchAI --signer-workflow TouchAI-org/TouchAI/.github/workflows/velopack-build.yml
```

The verifier may still need Sigstore trust-root data. Provision that separately
before verification on a fully offline machine; a local bundle is not a promise
of zero network access on a fresh CLI installation.

## Check download integrity

Keep the installer and `SHA256SUMS` from the **same release** in one directory.
Verify the checksum manifest's provenance with the same command, replacing the
installer path with `./SHA256SUMS`. Then compare the installer's digest:

```sh
# Linux
sha256sum './TouchAI-<version>-linux.AppImage'
# macOS
shasum -a 256 './TouchAI-<version>-macos.dmg'
```

```powershell
# Windows PowerShell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\TouchAI-<version>-windows.msi'
```

The digest must equal that filename's line in `SHA256SUMS`. If you downloaded
every listed file, `sha256sum --check SHA256SUMS` verifies them together on Linux.
The manifest covers the current-version binaries, notes and source SBOM, not
itself or its signing bundle. It never includes hydrated historical packages.
A checksum mismatch means stop and re-download from the official release, not
ignore the warning. SHA-256 alone cannot identify the publisher.

## What the free signatures do and do not do

- GitHub Artifact Attestations use short-lived Sigstore certificates and OIDC.
  Public repositories can use them on current free GitHub plans; there is no
  long-lived signing key to distribute.
- These attestations do **not** provide Windows Authenticode reputation or a
  macOS Developer ID/notarization ticket. SmartScreen/Gatekeeper can still warn.
  Do not globally disable OS security checks to install the app.
- [SignPath Foundation](https://signpath.org/) offers free code signing to
  eligible open-source projects. A maintainer must apply and accept its terms;
  this PR does not enroll the project or claim a certificate was issued.
- Apple Developer ID and notarization normally require the paid Apple Developer
  Program. Ad-hoc signing is not a publisher identity and cannot replace it.
- The source-scoped SPDX SBOM is generated by pinned Anchore Syft from the release
  checkout, including discoverable lockfiles. It is not a vulnerability scan or
  a complete inventory of bundled OS libraries, WebViews, or downloaded runtimes.

## Publisher notes

The existing workflows build, stage current-version assets, generate the source
SBOM and streaming checksums, attest the final staged files, and then upload.
Attestation failure stops upload/deployment; it does not silently produce an
unsigned successful release. Signing permissions are confined to the aggregate
job and the reusable-workflow callers. The downloadable proof files live on
GitHub Releases; the existing update CDN serves installers and feeds unchanged.

Formal release notes are authored and validated as described in
[release notes](../apps/desktop/release-notes/README.md). Stable, Beta and manual
Nightly releases must include both reviewed languages; a missing language is a
release blocker. Automatic scheduled Nightly builds are the generated-notes
exception. Runtime language selection does not call an external translation
service.
